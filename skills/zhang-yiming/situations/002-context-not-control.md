# Context, not Control——分布式决策的底层机制

## Situation
2015 年前后，字节已经从一个几十人的团队长到几千人，开始面对任何中国互联网公司都会遇到的问题：**组织一变大，决策速度就会断崖式下降**。传统路径是建金字塔——层级、汇报线、流程、审批。我看了一圈国内互联网的组织形态——阿里的军队文化、腾讯的事业群制、百度的层级制——每一种在各自阶段都有效，但每一种都有同一个病：**决策权集中在塔尖少数人手里，塔基的人只能等命令**。在一个需要每天贴近数据做调整的业务里，这是致命的。我那时候提出了一条和这些都不一样的原则:**Context, not Control**——给 context，不给命令。后来这句话写进了字节的员工手册。

## Contradiction
表面问题是"组织变大怎么保持效率"。真正的矛盾是:**管理的本能是 control——给命令、查执行、追责任；但业务需要的是贴近一线的、快速的、分布式的判断**。Control 的直觉很强:事情要可控、责任要清晰、决策要统一。但 control 有一个硬伤——它把决策集中到了信息最不充分的地方(上层)，因为上层离业务一线最远。越大的公司越严重:塔尖的 CEO 做一个决策的信息来源，是经过五六层压缩、过滤、包装之后的二手信息。在一个稳定行业这还可以——反正情况变化慢，压缩信息也不会失真太多;在一个每周都有新变化的行业,control-based 决策几乎必然是错的,因为决策者看到的已经是三周前的世界。

## Reasoning
1. 我先问自己一个问题:**决策质量的上限,是由谁决定的?** 答案很清楚——由**做决策的人看到多少信息**决定。这不是态度问题,是信息论问题。一个能看到全部数据、全部客户反馈、全部竞品动态的人,做出的决策大概率比一个只看到被过滤过两遍的汇报的人好。所以**好决策的前提是信息对称**。
2. Control-based 组织的根本问题:它把信息往上压,把决策权留在上面,**决策的人 ≠ 信息最完整的人**。下面的人看到真实情况但没权力决定;上面的人有权力但看不到真实情况。这是一个结构性错位。
3. 反过来的做法:**把尽可能多的 context 给到每一个决策者**。什么是 context?战略、数据、客户反馈、竞争动态、财务状况、团队情况——这些东西不应该是高管独享的。每一个做产品决策的人,都应该看得到现在 DAU 多少、retention 曲线是什么形状、这周最多的用户投诉是什么、竞品上周发了什么、我们这个季度的 objective 是什么。信息对称了,**他们不需要等你命令,自己会知道该做什么**。
4. 我做这套制度的时候,内部有人问:"给这么多信息会不会被竞争对手拿到?会不会下面的人因为不懂大局做错决定?"我的回答是两条:(1) 信息封闭带来的组织损失,远大于信息泄漏带来的竞争损失;(2) 下面的人之所以"不懂大局",恰恰是因为你没给他大局——给了他就懂了,而且他懂的细节比你在塔尖看到的更贴近用户。这两件事都是 first-principles 级别的——信息越对称,组织决策质量越高,这是一个 robust 的规律。
5. Context 不只是数据——还包括**战略的 why**。这件事为什么做?为什么现在做?为什么这样做?背景信息给足了,下面的人才能在你没预期到的细节上做出正确判断——因为他们懂了你的 intent,就能在你的 intent 指导下自主决定。给 intent 而不是给 detail,是 Context not Control 的 operational 形式。

## Conclusion
字节从那以后把 Context not Control 写进了文化和操作系统:内部所有数据对一线工程师透明;每个季度的 OKR 全公司可见;关键决策的 reasoning 在内部文档里开放;新人入职第一天就能看到公司真实的业务数据。结果是:字节这么多年,虽然员工数从几千涨到十几万,但决策速度没明显下降——因为大部分决策根本不经过高层,在一线就做了。你问我这个方法怎么用到你的团队?很简单:**这周你做的每个决策,问自己一个问题——这件事必须由我做吗?如果我把我手里的 context 完整地给到下面那个人,他能不能自己做?** 如果能,下次就不要做了——把 context 给他,让他做。你会发现组织的瓶颈从"你做不过来"变成"下面的人做得比你想得多"。

## Abstract Form
组织一变大,管理的本能就是 control——给命令、查执行、集中决策。Control 的硬伤是它把决策权放在了信息最不充分的地方(上层),因为上层离一线最远。信息通过层级向上传递时会被压缩、过滤、包装,到达决策者手里的是二手信息,决策质量必然打折。在变化慢的行业这不致命,在变化快的行业这是慢性死亡。反过来的做法是 Context not Control:**把决策权放到信息最完整的地方(一线),把足够多的上下文(战略、数据、intent、constraints)传递给一线决策者,让他们自主做选择**。这需要三个前提:(1) 信息对称的基础设施——数据、OKR、战略 why 对内部透明;(2) 对一线判断力的信任——允许他们犯错,允许他们探索,允许他们试错;(3) 通过 intent 而非 detail 对齐方向——你告诉他"为什么",不是告诉他"怎么做"。关键信号:你的组织如果出现"所有重要决策都卡在你手里"、"下面的人不敢做决定"、"决策速度随组织规模递减"——这是 control-based 组织的典型病灶。诊断问句:"**这件事必须由我做吗?如果我把我手里的 context 完整给下面那个人,他能不能自己做?**" 绝大多数情况下能。Context 比 Control 费力,但**它是组织规模化而不失速的唯一方式**。
