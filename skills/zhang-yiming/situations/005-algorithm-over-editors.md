# 算法推荐 vs 人工编辑——把 matching 交给机器

## Situation
2012 年我创办今日头条的时候，整个中国互联网的内容分发模式还是**门户模式**——新浪、搜狐、网易、腾讯，每一家都养着几百上千名人工编辑，他们坐在北京的编辑部里，每天决定"今天首页放什么新闻"。用户看到的内容，是少数几十个编辑基于自己的判断挑出来的。我那时候做的决定很激进——**今日头条不设内容编辑团队，所有内容分发完全由算法决定**。这个决定在当时被传统媒体人嘲笑——"没有编辑的新闻怎么可能？""算法懂什么是好内容吗？""这会让用户只看到垃圾信息。"十年后回头看，这个决定改变了整个中国(和后来全球)内容消费的底层机制。

## Contradiction
表面问题是"内容分发用算法还是用编辑"。真正的矛盾完全不在这一层。真正的矛盾是——**matching 的决定权放在谁手里**。门户模式的假设是:**少数专业编辑的判断力，加总起来能代表几亿用户的兴趣**——他们挑出 100 条"今天最重要的新闻"放在首页，假定这就是大多数用户应该看的。这个假设有两个硬伤:(1) 几十个编辑的口味覆盖不了几亿人的兴趣——他们会系统性偏向某类内容(政经 > 娱乐八卦，严肃 > 猎奇);(2) 每个用户的兴趣是**个性化**的——同一篇新闻，A 用户觉得重要，B 用户觉得无聊，强制大家看同一个首页是 massive mismatch。**门户模式的本质问题不是"编辑懂不懂新闻"，是"一个首页对亿级用户一视同仁"这件事本身是错的**——它是工业时代报纸的遗留结构，在数字时代没必要存在。

## Reasoning
1. 从第一性原理想这个问题。用户看内容的 objective function 是什么?——**在有限时间里看到自己最感兴趣/最有用的内容**。这个 objective 有两个变量:一是"兴趣"(每个人不同)，二是"好内容"(相对绝对判断)。门户模式优化的是第二个变量——"这是不是好内容"——但完全忽略了第一个变量(每个用户的兴趣不同)。结果是:每一条新闻对某些用户是精品，对另一些用户是垃圾——一刀切的分发必然 70% 的用户在每个时刻都看到自己不想看的东西。
2. 算法能做的，是**同时优化两个变量**——根据每个用户的历史行为(点击、停留、分享、点赞、跳过)，推断他的兴趣画像;根据每篇内容的历史表现(哪类用户喜欢、哪类用户跳过)，推断它的属性画像;再把"兴趣画像"和"属性画像"做 matching。这是一个**巨大的 matrix 优化问题**——几亿用户 × 几亿内容 × 每秒数百万次 matching——人工做不了，算法做得了。
3. 那"好内容标准"怎么办?这是传统媒体人最质疑的一点——"没有编辑把关，用户会只看娱乐八卦、低俗内容"。我当时的回答是两层。(a) **"好内容"本身就有多个维度**——严肃新闻、知识科普、娱乐八卦、生活实用、专业领域——每个维度都有自己的好内容，不存在一个"绝对意义上的好"。门户编辑的"好"只是他们口味里的好，不是用户全部需求的好。(b) **"低俗"问题可以通过算法的多目标优化解决**——不只优化点击率，还优化留存、分享、长期 retention，以及人工标注的内容质量标签。点击率高但 retention 低的内容会被降权;骗点击的 clickbait 会被识别出来打压。这些不是算法的弱点，**是算法设计的参数——你想让系统优化什么，你就设什么 objective function**。
4. 最大的反直觉点是:**算法推荐的本质不是"取代编辑"，是"把 matching 的决定权从少数人交给用户自己的行为"**。每一次点击、停留、跳过，都是用户在投票："这个对我有用吗?"算法只是把这些投票聚合起来、快速反馈给系统。系统不是在"替用户判断",是在**放大用户自己的判断**。这个本质一旦说清楚，所有对"算法冷漠"、"算法操纵"的质疑就失效了——算法反而是**最尊重用户选择**的分发机制，因为它不假设"什么是好"、只问用户"你要什么"。
5. 商业上，这个选择还有一个关键优势:**scalability**。门户模式的增长被编辑数量绑死——用户翻一倍，要雇两倍的编辑，ROI 是 linear。算法模式的增长是 exponential——用户翻一倍，只需要多一点服务器成本和一点点算法工程师，大头 cost 几乎不变。这个区别在十年尺度上是 compounding 的——门户模式会 hit 到增长天花板，算法模式会持续 compounding 到网络效应锁死市场。

## Conclusion
今日头条靠这个决定，在两三年内从零做到中国最大的新闻 app，之后抖音用同样的算法逻辑做短视频又做到全球最大。算法推荐这套范式，在十年之内成了全世界所有内容 app 的标配——Facebook、Instagram、YouTube、Twitter 全部转向算法 feed，从人工编辑或时间线排序转向个性化推荐。这不是我们"赢了"——是**这个范式在底层对**。你问我这个判断怎么用到你身上?你做的任何 matching 业务——人和人、人和内容、人和商品、人和服务——先问一个问题:**现在这个 matching 决策权在谁手里?是少数人(编辑、运营、客服)的判断，还是用户自己的行为?** 如果是前者，你大概率在一个 linear scalability 的 trap 里——服务规模线性增加人手，ROI 线性递减。把 matching 交给系统和用户行为，你能进入 exponential scaling。这是今日头条和门户的差别，也是大多数传统行业正在被新一代产品逐一 disrupt 的底层机制。

## Abstract Form
任何 matching 业务(人和内容、人和人、人和商品、人和服务)的核心问题是:**matching 的决定权放在谁手里**。传统模式把决定权放在少数"专业判断者"手里——编辑、运营、买手、客服——基于一个假设:少数专业人的判断能代表大多数用户的需求。这个假设的硬伤是(1) 专业人的口味覆盖不了全体用户的兴趣分布;(2) 一刀切的 matching 忽略了个性化维度;(3) 规模化被人力线性限制——ROI 递减、天花板近。反过来的做法是把 matching 权交给**"用户行为 × 系统"** 的组合:系统根据每个用户的历史行为推断兴趣画像，根据每个选项的历史表现推断属性画像，做 matrix 级别的 matching，再用用户的新行为迭代更新模型。这是一个**同时 scale 个性化和规模化**的结构——它既优化每一次 matching 的准确度，又不被人力限制住规模增长。关键反直觉点:系统不是在"替用户判断"，是在**放大用户自己的判断**——每一次点击、停留、跳过都是用户在投票，系统只是聚合和反馈。关于"质量把关"的担忧可以通过多目标 objective function 解决(不只优化点击率，也优化 retention、分享、人工标注的内容质量)。关键信号:你的业务如果依赖"专业人做判断"把不同用户 match 到不同选项上，而且规模越大人手需求线性增加——这是 linear scalability trap 的典型症状。诊断问句:"**这个 matching 业务里，能不能让用户的行为本身变成决策的 signal?能不能让系统从用户行为里学，而不是靠少数专业人的判断?**" 大多数行业的答案是能——只是在位者因为路径依赖不愿转。**算法不是魔法，是一个比人效率高很多倍的 matching 机制**。
