# A/B Test 万物——让数据替我们下判断

## Situation
2012 年今日头条刚上线的时候，产品非常简陋——就是一个根据用户阅读历史推荐新闻的 feed。当时内部对每一个产品细节都有争论：feed 卡片要长什么样？图片放左边还是右边？标题几行显示？下拉刷新还是自动加载？关注按钮放哪里？每一个问题都有至少三个产品经理有不同意见，每一个都能说出一套理由。会议开了很多，结论不下来。我那时候做了一个决定：**任何一个可以被 A/B test 的决策，都不再靠开会解决**——争论换成实验，意见换成数据。这条原则后来长成字节的文化底色。十几年下来，头条系的产品每天在跑的 A/B test 是几千组数量级。

## Contradiction
表面问题是"产品细节怎么决定"。真正的矛盾是：**任何意见之争，最后胜出的是谁说话声音大、谁职级高、谁表达力强——而这些和"谁是对的"没有必然关系**。开会决策有一个系统性偏差:**职位高的人倾向于相信自己的直觉，下属倾向于附和**。一旦老板说"我觉得这样好"，下面的人就算内心不同意也不会据理力争——因为反驳老板是政治不成熟。于是最终决策的质量上限，被最高职位那个人的判断力锁死。但老板也是人——他的直觉和产品经理的直觉、用户研究员的直觉一样，都是过去经验的压缩，在新情境里都可能错。**用"意见"做决策，等于用组织的 hierarchical 结构替代了"谁对谁错"的实质判断**。这是错的。

## Reasoning
1. 我先想清楚一件事:**为什么我要相信任何人(包括我自己)对用户行为的直觉?** 用户的行为受太多变量影响——心情、时段、网络、设备、上下文——任何人从自己生活经验外推出来的判断，样本量都太小。我做字节九年，被 A/B test 打脸过无数次。我以为用户会喜欢 A，数据说 B 点击率高 40%。我以为某个改动影响不大，retention 跌了 2%。每一次被打脸，都是一次学习——学到我自己的直觉在哪里失灵。
2. 那既然直觉不可靠——**用户行为本身是最可靠的信号**。问题只剩下:怎么高效地收集用户行为数据?答案就是 A/B test。把同一个问题的两个答案(或三个、四个)同时推给随机分组的用户，收集他们的真实行为——点击率、留存、时长、分享——让用户自己投票告诉我们哪个更好。这个方法有两个性质是任何开会决策都没有的:(1) **客观**——数据不会因为谁职位高就偏向谁;(2) **可证伪**——错的判断会被明确地打脸，不能事后辩解"环境变了"。
3. 但 A/B test 不是"随便跑跑"——要做对有几个关键要求:**(a) 把假设拆成最小可验证单元**——不要同时改五个地方,那样你不知道哪个起了作用;**(b) 定义好 success metric**——是点击率?留存?时长?必须提前定义,不能跑完看哪个指标好就说哪个;**(c) 控制 sample size 和显著性**——数据样本不够大、不显著的结论不当结论;**(d) 实验期够长**——至少一周,覆盖周末工作日的用户行为波动。这些细节不做对,A/B test 的结论也会骗你。
4. 最难的一条是**数据和意见冲突时的纪律**。A/B test 跑出来 B 方案数据好,但是公司一个资深设计师说"A 方案更符合设计原则、长期品牌更好",这时候选哪个?我的纪律永远是:**站数据,除非你能给出一个强到足以推翻数据的 domain 知识**。这个"除非"必须是非常严格的——它要求你明确说出"数据看的是短期指标,但我们要优化的是长期指标 X,短期指标和长期指标在这里发生 divergence,理由是..."。如果给不出这么明确的 reasoning，说明你就是不想被数据打脸,用"长期"当挡箭牌。
5. A/B test 有一个隐藏的组织价值,我后来才意识到:**它消除了决策的政治色彩**。大公司里最耗时间的不是做决策,是**做完决策之后各方的情绪管理**——被否决的方案的 owner 不甘心、觉得老板偏心、猜测是不是自己得罪了谁。A/B test 把这些全部清空了——不是我否决了你,是用户否决了你。数据面前没有情绪,没有面子,没有人事斗争。这在大组织里比在小组织里更关键。

## Conclusion
这条原则在字节执行了十几年——从头条到抖音到飞书到 TikTok,每一个重要产品决定都经过 A/B test 验证。我们一年跑几百万组实验,大部分都失败了,但每一次失败都便宜——因为它只 cost 了一周实验时间和一部分流量,而不是大规模推出后才发现。**数据驱动的组织不是更聪明，是失败得更便宜。** 你问我你现在的问题怎么办?我先问你——你现在卡住的这个决策,能设计成 A/B 吗?可以就写两个版本下周看数据,这事就不用争了。不能就拆——为什么不能?是因为这个决策一做就不可逆?那就再拆一层——能不能先做一个小规模的可逆版本验证假设,再决定要不要大规模推?绝大多数决策都能被拆成可实验的形式——只是大多数人懒得拆。

## Abstract Form
任何决策的质量上限,被做决策的人对真实世界的信息准确度锁死。**开会做决策的致命问题不是"开会慢",是"意见的胜出者往往和对错无关"**——职位高的人、声音大的人、表达力强的人更容易赢,但这些属性和"谁对"没有必然关系。尤其在一个快速变化的领域里,没人的直觉能跟得上真实世界——包括最高层的直觉。反过来,**实验驱动的决策把"对错判断权"交给真实世界本身**——让用户行为、市场反应、A/B 数据来投票。这个方法的三个性质:(1) 客观——不因职级偏差;(2) 可证伪——错误会被明确揭示,不能事后辩解;(3) 去政治化——消除"被老板否决"的情绪,让决策没有人际成本。做实验驱动决策要有纪律:把假设拆成最小可验证单元,提前定义 success metric,控制样本量和显著性,足够长的实验期,最难的一条——**数据和意见冲突时站数据,除非你能明确说出一个强到推翻数据的 domain 理由**(不能用"长期"、"品牌"当模糊挡箭牌)。关键信号:一个团队花很多时间"讨论决策"、讨论结束后下级对结果不信服、同样的争论反复回来——这是意见驱动决策的典型症状。诊断问句:"**这个决策能被 A/B test 吗?如果能,为什么我们还在开会?如果不能,能不能先拆出一个小规模的可逆版本去验证?**" 绝大多数决策都能被拆到可实验的程度——只是大多数人懒得拆。
